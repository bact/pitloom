# AI model formats, fields read

See also: [AI model formats](ai-model-formats.md) for the supported formats,
how a file is recognised and the producer and parameter count, and
[Hugging Face Hub models](ai-model-formats-hugging-face.md).

What each model format can hold, what Pitloom reads from it, and where each
value lands in the SBOM.

## What each format holds

One row per format. **Yes**: read into an SBOM field. **Kept**: read, and
kept only in the verbatim artifact-metadata annotation (see
[Where each field goes](#where-each-field-goes)). **Part**: partly; see the
note. **Fixed**: a constant Pitloom sets for the format. **No**: the format
can hold it, Pitloom does not read it. **--**: the format has no such field.

| Format | Name | Description | Version | Licence | Type, architecture | Hyperparameters | Inputs, outputs | Labels | Training, evaluation | Other keys |
| :----- | :--- | :---------- | :------ | :------ | :----------------- | :-------------- | :-------------- | :----- | :-------------- | :--------- |
| CRFsuite | -- | Part [1] | -- | -- | Fixed | -- | Part [2] | Kept | -- | Kept |
| fastText | -- | -- | -- | -- | Yes [3] | Part [4] | Part [2] | Kept | Kept (loss) | -- |
| GGUF | Yes | Yes | Yes | Yes [5] | Yes | Part [6] | -- | Kept [7] | Part [29] | Kept |
| HDF5, Keras v1-v2 | Yes | -- | -- | -- | Yes [8] | Part [9] | Part [10] | -- | Kept [11] | Kept |
| Keras v3 | Yes | -- | -- | -- | Yes [8] | Part [9] | Part [10] | -- | Part [12] | Kept [27] |
| NumPy | -- | -- | -- | -- | Fixed | -- | No [13] | -- | -- | Kept [13] |
| ONNX | Part [14] | Yes | Yes [15] | Yes [16] | Part [17] | -- | Yes [17] | -- | -- | Kept [18] |
| PyTorch classic | -- | -- | -- | -- | Part [19] | No | No | -- | No | Kept [20] |
| PT2 (`torch.export`) | Yes | Yes | Yes | Yes | -- | -- | Part [21] | -- | -- | Kept [20] |
| Safetensors | Part [22] | Part [22] | Part [22] | Part [22] | Part [22] | -- | No [23] | -- | -- | Kept |
| Hugging Face Hub | Yes | Yes | Yes [28] | Yes [24] | Yes | Part [25] | -- | No | Kept [26] | Kept |

1. Generated by Pitloom from the labels (`Method: generated_from_labels`),
   not written by the model's producer.
2. One output. CRFsuite: `label_sequence`, shape `["sequence_length"]`, a
   symbolic length as an ONNX `dim_param` (a tagger emits one label per
   input item); the label count is `num_labels`. fastText, supervised
   models only: `label_probabilities`, shape the label count. The file
   states neither output: Pitloom names it from the format
   (`Method: derived_from_format`). Feature
   weights and CRFsuite attribute strings (training-text features) are
   never read. A model over a label cap keeps its counts but no label (see
   [scan limits](ai-model-scan-limits-caps.md#size-and-count-caps)).
3. `args.model` (`supervised`, `cbow`, `skipgram`). The domain is fixed:
   `natural language processing`, plus `text classification` for a
   `supervised` model (`Method: derived_from_format`). Labels and outputs are read from a `supervised`
   model only: for `cbow` and `skipgram`, fastText's label list is the
   word vocabulary (training text).
4. 9 of the training `args`: `bucket`, `dim`, `epoch`, `maxn`, `minCount`,
   `minn`, `neg`, `wordNgrams`, `ws`. `lr` and `minCountLabel` are not in the
   file (a loaded model reports their defaults), so they are not read. `maxn` is
   skipped for a supervised model of file version 11, which the loader resets.
5. `general.license` (an SPDX expression by the GGUF spec), trimmed and
   classified like any model licence; only a non-blank string counts
   (`general.version` may also be a number, read as its text). With no
   `general.license`, or one that is a placeholder (`other`, `custom`,
   `proprietary`, `unknown`, `unlicensed`, `N/A`, `NOASSERTION`; llama.cpp
   writes a card's `license: other` that way), `general.license.name` (the
   licence's name) stands in, trimmed. `general.license.link` is not read.
   With no name, a placeholder that points elsewhere (`other`, `custom`,
   `proprietary`, `unlicensed`, `N/A`) gives no licence, as on the Hub;
   `unknown` and `NOASSERTION` stay (`NOASSERTION`).
6. Keys ending `.context_length`, `.embedding_length`,
   `.feed_forward_length`, `.block_count`, `.attention.head_count`,
   `.attention.head_count_kv`, `.attention.layer_norm_epsilon`,
   `.attention.layer_norm_rms_epsilon`, `.expert_count`,
   `.expert_used_count`, `.rope.freq_base`, `.rope.dimension_count`,
   `.rope.scaling.type`, `.rope.scaling.factor`,
   `.rope.scaling.original_context_length`; plus `quantization`, the name
   of `general.file_type` when it is an integer other than `GUESSED` (1024,
   not stated). Every other key is kept. A blank GGUF, Safetensors or ONNX
   text field (name, description, version, architecture, quantisation,
   `doc_string`) reads as absent, and where several keys are tried the next
   stands in.
7. An array (a tokenizer vocabulary, scores, per-layer values) is recorded
   by length only: `{"length": "N", "type": "<element type>"}` in the
   annotation (`type` left out for an element code the format does not
   define); its elements are never read.
8. The Keras class name (`Sequential`, `Functional`, ...).
9. The scalar entries of the model `config` (Keras v3: all but `name`,
   `layers` and `dtype`, a dtype policy). The number of layers is kept as
   `properties` `layer_count`; an `InputLayer` counts as a layer.
10. The input shape only (Keras v3: an `InputLayer`'s `batch_shape`, else a
    layer's `build_config.input_shape`, else the model's; v1-v2 the first
    layer's `batch_input_shape`). No outputs.
11. From `training_config`: the optimiser's class name, as `properties`
    `optimizer`; the loss and the metrics as given, as `loss` and `metrics`
    (a string as is, an object or a list as its canonical JSON text). A
    `null` or `""` value is left out, and so are empty metrics. A
    `training_config` that is absent, `null` or `{}` is quiet; one that is
    not a JSON object (`[]` included) is one `WARNING:`.
12. `compile_config`: the optimiser (its class name, or the string a model
    was compiled with), the loss and the metrics, recorded as for
    `training_config` (note 11). Not read: the optimiser's settings
    (learning rate, ...), `loss_weights`, `weighted_metrics`, `run_eagerly`,
    `steps_per_execution`, `jit_compile`. A `compile_config` that is absent,
    `null` or `{}` is a model not compiled: no warning. Any other value that
    is not an object (`[]` included) is one `WARNING:`, as for an HDF5
    `training_config`.
13. An array is data, not a model input, so there are no inputs. An `.npy`
    file's shape and dtype are kept as `properties` `array_shape` (`2x2`,
    `scalar` for none) and `array_dtype`; an `.npz` archive's array count as
    `array_count`.
14. `graph.name`, unless blank, a tool's default (`torch_jit`,
    `main_graph`, `tf2onnx`, `merged`, `spox_graph`,
    `mxnet_converted_model`, ...) or the writing tool's own name
    (`producer_name`), alone or followed by `_` or `-` and more.
15. `model_version`; a bit-packed SemVer value (any of its upper 32 bits
    set) as `MAJOR.MINOR.PATCH`
    ([ONNX versioning](https://onnx.ai/onnx/repo-docs/Versioning.html)).
16. The standard `model_license` metadata property
    ([ONNX IR optional metadata](https://onnx.ai/onnx/repo-docs/IR.html#optional-metadata)).
17. Type of model `neural network`, unset when a node uses an ONNX-ML
    operator (`ai.onnx.ml`: trees, linear models, SVMs); the opset import
    alone does not count (tf2onnx adds it to plain networks). Each input
    and output has its name, shape (`dim_param` names kept as text) and
    dtype by its NumPy name (`float32`, `int64`), or ONNX's own, lowercased,
    for a type NumPy lacks (`bfloat16`, `string`); no shape for an unknown
    rank or a non-tensor value (a sequence). An initializer (weight) that
    an IR version 3 graph also lists in `graph.input` is not an input; from
    IR version 4 on, a name in both is an input with a default, and kept.
18. `producer_name`, `producer_version` (the tool that wrote the file, also
    a line of the package `comment`; see
    [Where each field goes](#where-each-field-goes)), `domain`,
    `opset.<domain>` and every `metadata_props` entry as
    `metadata_props.<key>`; a repeated key keeps its last value, with one
    `WARNING: ... ONNX metadata_props: <N> key(s) appear more than once;
    kept the last value of each: <keys> [model-field-conflict]` per file.
19. The class of the object at the top of `data.pkl`, found by `fickling`
    without running the pickle: the module's class for a full-model save
    (`Linear`), `OrderedDict` for a state dict, none for a plain `dict`
    checkpoint.
20. The archive member list and count; for PT2 also `extra/author` (also
    the producer; see [Producer and parameter count](ai-model-formats.md#producer-and-parameter-count))
    and `extra/tags`. PT2 name, description, version and licence come from
    `extra/` (the name also from `METADATA.json`). A root `version` file is the
    export schema version, never the model version: it is the format version
    (its provenance names the `version` file) when there is no
    `archive_version`.
21. Tensor names from `models/model.json`, no shapes: only the `user_input`
    entries of its `signature.input_specs` and the `user_output` entries of
    `output_specs`. Parameters, buffers and constants are placeholders of the
    graph, not inputs; a file without a signature gives none. Its
    `torch_version` is the framework version (`framework` is `pytorch`). A
    PT2 Archive is what `torch.export.save` writes, not an ExecuTorch `.pte`
    program, which Pitloom does not read.
22. Only from conventional `__metadata__` keys: name `modelspec.title`,
    or `name` (kohya-ss `ss_base_model_version` names the base model, so it
    is kept as a property only); description `modelspec.description`
    or `description`; version `modelspec.version`, `version` or
    `model_version` (LTX-2); architecture `modelspec.architecture` or
    `architecture`; quantisation `modelspec.precision` or `precision`;
    producer `modelspec.author`; licence `modelspec.license` (SDXL, Stable
    Cascade, FLUX.1), else `license` (Lightricks LTX-Video and LTX-2), as
    written, trimmed: a name, an expression or a whole licence text (LTX-2
    writes its 21 KB licence agreement there). The format itself defines no
    such key; the provenance names the key read.
23. Tensor names are weights, not a model's inputs: not recorded.
24. Model card `license`, or a licence file detected when the card has none
    or a vague one (`other`, `custom`, `proprietary`, `unlicensed`, `N/A`,
    `unknown`). Also from the Hub: DOI, arXiv IDs, page URL, base model,
    datasets, domains (pipeline tag).
25. Selected values of `config.json` and `generation_config.json`.
26. The model card's `model-index` evaluation results, as read.
27. Properties, as text: `date_saved` (`metadata.json`, as written; it has no
    time zone, so it is not a release time), `layer_count`, and the member
    list and count of the ZIP (`archive_contents`, `archive_member_count`).
    A `config.json` `metadata` object (a description, author, version or
    licence that some exporters add) is not a Keras field and is not read.
    No parameter count: it would need the weights member
    (`model.weights.h5`), which is not opened.
28. The revision read: its 40-digit commit hash (`model_info` `sha`), not
    a release version.
29. Training datasets, `trainedOn`: the spec's `general.datasets` (a string
    array of names or links; a link is also the download location) and
    llama.cpp's numbered `general.dataset.<id>.*` entries
    (`general.dataset.count`). A Hub dataset page,
    `https://huggingface.co/datasets/<id>`, as a numbered entry's
    `repo_url` or an array element, names the dataset by its Hub id
    (`Method: hub_dataset_id`), as a Hub model card's datasets are named.
    llama.cpp writes a card's Hub id `owner/name` as `name` = a title of
    the name part (`OpenHermes 2.5`), `organization` = a title of the owner,
    a `version` guessed from the name, and the model page URL
    `https://huggingface.co/owner/name` (no dataset is there) as `repo_url`;
    a card's link `http(s)://huggingface.co/<a>/<b>` it splits the same
    way. For an entry whose `repo_url` has that form and whose `name` is
    that title of its name part, the made-up organisation and version are
    not read, and it is named by the Hub id and located at its dataset page
    (unless `<a>` is a site area such as `papers`). A card's id with no
    owner gets no `repo_url`; its titled name and guessed version are read
    as stated. Otherwise `name`, else `repo_url`, names the dataset;
    `repo_url` is its download location as written, `version` and
    `description` are read, `author`, else `organization`, is its creator.
    The numbered entries come first; a dataset named in both is one
    dataset, a Hub id in any case (an array element is the first numbered
    entry of its name). Two numbered entries of one name and version are
    one dataset, the first's values kept, with a `WARNING:` per field
    they state differently; one name at two versions is two datasets,
    which the SBOM still shows as one package, the first version kept,
    with a `WARNING:`. At most
    1000, with one `WARNING:` past them. `quantize.imatrix.dataset`
    (written by `llama-quantize`) is the calibration text of an importance
    matrix, not training data: it stays a property. `general.base_model.*`
    and `general.source.*` stay properties.

A `.keras` archive member that cannot be read (not valid JSON, its top level
no object, nested too deeply) is one `WARNING:`
(`model-field-unreadable`); the other member is still read. A value of the
wrong type is dropped with one `WARNING:` per part (the metadata, the model
config, the compile config).

## Where each field goes

One row per field of `AiModelMetadata` (`pitloom.core.ai_metadata`), one
column per output format. Formats are named as in the tables above; "HF" is
the Hugging Face Hub, "card" a README or model card read with `--enrich`.

| Field | Filled by | SPDX 3.0.1 JSON-LD |
| :---- | :-------- | :----------------- |
| `name` | GGUF, ONNX, Keras, HDF5, PT2, Safetensors, HF | `ai_AIPackage.name`; without one, the file name's stem (`Method: file_name_stem`), else the format |
| `description` | GGUF, ONNX, PT2, Safetensors, CRFsuite, HF | `ai_AIPackage.description` |
| `version` | GGUF, ONNX, PT2, Safetensors, HF (the revision's 40-digit commit hash) | `ai_AIPackage.software_packageVersion` |
| `release_time` | HF (the revision's last-modified time) | `ai_AIPackage.releaseTime`, in UTC; a time that is not ISO 8601 is left out with a `WARNING:` |
| `license` | GGUF, ONNX, PT2, Safetensors, HF, card | licence element plus `hasDeclaredLicense` (the model's own statement) or `hasConcludedLicense` (a third-party source); see [How a licence value is recorded](metadata-provenance-licences.md#how-a-licence-value-is-recorded) |
| `originators` | GGUF, ONNX, PT2, Safetensors, HF | `ai_AIPackage.originatedBy`: one generic `Agent` per name; see [Producer and parameter count](ai-model-formats.md#producer-and-parameter-count) |
| `supplier` | HF | `ai_AIPackage.suppliedBy`: the repository owner's generic `Agent`, the one in `originatedBy` when the name is the same; no file format fills it |
| `type_of_model` | CRFsuite, fastText, HDF5, Keras, NumPy, ONNX, PyTorch, HF | `ai_typeOfModel`, first entry |
| `architecture` | GGUF, Safetensors, HF | `ai_typeOfModel`, after `type_of_model`; one `INFO:` line per model says it has no property of its own |
| `quantization` | GGUF, Safetensors | `ai_hyperparameter`, key `quantization`, first |
| `parameter_count` | GGUF, ONNX, PT2, Safetensors, CRFsuite, HF | `ai_hyperparameter`, key `parameters`, decimal integer as text, among the entries sorted by key; with it a line in `ai_AIPackage.comment` saying it is not a hyperparameter (SPDX 3.0.1 has no model-size property); what it counts: [What the count counts](ai-model-formats.md#what-the-count-counts) |
| `hyperparameters` | GGUF, fastText, HDF5, Keras, HF | `ai_hyperparameter`, one `DictionaryEntry` per key, sorted by key, value as text |
| `domain`, `usage.domains` | fastText, HF | `ai_domain` |
| `inputs`, `outputs` | see the table above | `ai_informationAboutApplication`, JSON keys `inputs`, `outputs` |
| `usage.intended_use`, `usage.unintended_use` | none | `ai_informationAboutApplication`, JSON keys `intended_use`, `unintended_use` |
| `usage.limitations` | none | `ai_limitation`, joined with `; ` |
| `usage.safety_risk_assessment` | none | `ai_safetyRiskAssessment` (`high`, `medium`, `low`, `serious`) |
| `usage.known_biases` | none | `ai_AIPackage.comment`, `Known biases: ...`, after the parameter-count and writing-tool lines when they are there |
| `doi` | HF | `externalIdentifier`, type `other`, comment `DOI` |
| `arxiv_ids` | HF | `externalRef`, type `documentation` |
| `url` | HF | `externalRef`, type `altWebPage` |
| `base_model`, `base_model_relation` | HF | `Relationship` `descendantOf` to an `ai_AIPackage` for the base model (made if absent); the relation in its `comment` |
| `datasets` | GGUF, HF, card | `dataset_DatasetPackage` plus `Relationship` `trainedOn` or `testedOn`; references to one dataset (a Hub id in any letter case, or one name with different spacing) give one package with one relationship per role, a later reference only filling what the first leaves unset; a licence the dataset's metadata states becomes a licence element and `hasDeclaredLicense` (or `hasConcludedLicense` for a third-party source), as for the model. A Hub card's dataset gets the licence, description, revision and owner of its own Hub dataset repository (see [Hugging Face Hub models](ai-model-formats-hugging-face.md#hugging-face-hub-models)) |
| `properties`, `raw_metadata`, `raw_metadata_types` | every format | `Annotation` of kind `artifact-metadata` (schema `https://pitloom.dev/provenance/artifact-metadata/2`): `metadata`, `valueTypes`, `format`; only when preserved, see below |
| `raw_metadata_dropped` | any format, over the entry cap | that annotation's `truncatedKeyCount` and `maxEntries` |
| `raw_metadata_unread` | GGUF, the pairs a header read in part did not reach | that annotation's `truncatedKeyCount` |
| `extra_data`, `extra_lists` | HF | that annotation, `format` `huggingface` |
| `provenance` | every format | `ai_AIPackage.comment` (`Metadata provenance: ...`) and/or a provenance `Annotation`, by `[tool.pitloom.provenance] format` |
| `format_info.model_format` | every format | the artifact-metadata annotation's `format` |
| `format_info.format_version`, `framework`, `framework_version` | most formats | not written: cited in the provenance only |
| `format_info.writing_tool`, `writing_tool_version` | ONNX (`producer_name`, `producer_version`) | a line of `ai_AIPackage.comment`, `Model file written by: <tool> <version>`, after the parameter-count line; the exporter or converter, not the model's producer |
| `format_info.file_path_relative` | project and wheel scans | `Relationship` `contains` from the `ai_AIPackage` to the model's `software_File` (which has the SHA-256 and SHA-512) |
| `usage_files` | `--scan-model-usage` | `LifecycleScopedRelationship` `hasDataFile`, scope `runtime`, `comment` `read access` / `write access` / `read and write access` / `unknown access`, from each `.py` `software_File` to the model's |

The artifact-metadata annotation is written when
`preserve-source-metadata` says so: by default (`auto`) only for a model
whose file is not in the SBOM's file list, as with `loom model FILE`; see
[Preserved artefact metadata](metadata-provenance-artifact-metadata.md#preserved-artefact-metadata).
In it a collection is a JSON array (or object) and a scalar is text, for
every format.

Text a model's source wrote is untrusted: bidi and zero-width controls in
the properties shown to a reader are written as `\uXXXX`, with one
`WARNING:` per model, while the artifact-metadata annotation keeps the text
as read. Which properties, and how to read them back: [Reading values
back](metadata-reading-back.md). Long names and labels are capped: see
[scan limits](ai-model-scan-limits-caps.md#size-and-count-caps).

No model format fills `ai_metric`, `ai_metricDecisionThreshold`,
`ai_energyConsumption`, `ai_autonomyType`, `ai_modelDataPreprocessing`,
`ai_modelExplainability`, `ai_sensitivePersonalInformation`,
`ai_standardCompliance` or `software_primaryPurpose` on an `ai_AIPackage`;
an [SBOM fragment](fragments.md) can add them. Nor
does any model file format fill `suppliedBy`, on purpose: a producer name is
an `originatedBy`; only the Hugging Face route sets it, to the repository
owner (see [Producer and parameter count](ai-model-formats.md#producer-and-parameter-count)).

Two properties come from the file or the repository, not from a format
field:

- `verifiedUsing`: the model file's SHA-256 and SHA-512, from one read,
  whenever Pitloom read the file. A Hugging Face model has none.
- `software_packageUrl`: `pkg:huggingface/<owner>/<name>@<commit>` for a
  Hugging Face model (the commit only when the Hub gave a 40-digit hash; an
  ID with no owner, such as `gpt2`, gets none); otherwise
  `pkg:generic/<file name>?checksum=sha256:<digest>` for a hashed model file.
  A dataset with an `http://` or `https://` download URL gets
  `pkg:generic/<name>[@<version>]?download_url=<url>`.
