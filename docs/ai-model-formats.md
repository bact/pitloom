# AI model formats

See also: [AI model scan limits](ai-model-scan-limits.md) for why a model
can be missing metadata, and [Metadata provenance](metadata-provenance.md)
for the annotations named below.

Use this when you want to know which AI model file formats `loom model`
reads, what each format can hold, what Pitloom takes from it, and where
each value ends up in the SBOM.

## Quick guide

```bash
pip install "pitloom[ai]"
loom model path/to/model.safetensors -o model.spdx3.json
```

`pip install "pitloom[ai]"` installs every optional reader library below;
install a single extra (`pitloom[gguf]`, ...) if you need one format only.
Every reader is read-only: Pitloom never runs model code and never calls
`pickle.load()`. See [Command line](cli.md) for `loom model` and the other
targets that scan for models.

## How a file is recognised

A file is a model when its header confirms a format. The header check comes
first, so a file named on the command line is read whatever its suffix (a
`x.dat` with GGUF magic is GGUF); a project or wheel scan only looks at the
suffixes below. A header that contradicts the suffix (text named `.gguf`)
is not a model, and a Git LFS pointer is never one; see
[What is a model](ai-model-scan-limits.md#what-is-a-model).

| Format | Suffixes scanned | Header check | Reads | Library (extra) |
| :----- | :--------------- | :----------- | :---- | :-------------- |
| CRFsuite | `.crfsuite`, `.model` | magic `lCRF` | header and label strings | none |
| fastText | `.ftz`, `.bin` | magic `BA 16 4F 2F` | whole model, in memory | `fasttext-community` (`fasttext`) |
| GGUF | `.gguf` | magic `GGUF` | key-value header (memory-mapped) | `gguf` (`gguf`) |
| HDF5, Keras v1-v2 | `.h5`, `.hdf5` | HDF5 magic, or any non-empty file (a userblock moves the signature) | root attributes | `h5py` (`hdf5`) |
| Keras v3 | `.keras` | ZIP | `config.json`, `metadata.json` | none |
| NumPy | `.npy`, `.npz` | `.npy`: magic `\x93NUMPY`; `.npz`: ZIP | array headers | `numpy` (`numpy`) |
| ONNX | `.onnx` | none: any non-empty file | whole protobuf, in memory; external data files not loaded | `onnx` (`onnx`) |
| PyTorch classic | `.pt`, `.pth` | ZIP, or pickle protocol 2-5 (a text `.pth` path file is not a model) | archive listing, top of `data.pkl` | `fickling` (`pytorch`), optional: without it, no type of model |
| PT2 / ExecuTorch | `.pt2` | ZIP | archive listing, small text and JSON members | none |
| Safetensors | `.safetensors` | 8-byte little-endian header size, then `{` | JSON header | `safetensors` (`safetensors`) |
| Hugging Face Hub | model ID or URL, not a file | -- | Hub API, model card, config files | `huggingface_hub` (`huggingface_hub`) |

An HDF5 file with a `keras_version` attribute is reported as format
`keras`, otherwise as `hdf5` (and then only its format is recorded).
`.bin` and `.model` are shared with other tools: such a file is a model only
when it carries a supported format's magic (usually fastText or CRFsuite), and no
warning is given otherwise.

## What each format holds

One row per format. **Yes**: read into an SBOM field. **Kept**: read, and
kept only in the verbatim artifact-metadata annotation (see
[Where each field goes](#where-each-field-goes)). **Part**: partly; see the
note. **Fixed**: a constant Pitloom sets for the format. **No**: the format
can hold it, Pitloom does not read it. **--**: the format has no such field.

| Format | Name | Description | Version | Licence | Type, architecture | Hyperparameters | Inputs, outputs | Labels | Training, evaluation | Other keys |
| :----- | :--- | :---------- | :------ | :------ | :----------------- | :-------------- | :-------------- | :----- | :-------------- | :--------- |
| CRFsuite | -- | Part [1] | -- | -- | Fixed | -- | Part [2] | Kept | -- | Kept |
| fastText | -- | -- | -- | -- | Yes [3] | Part [4] | Part [2] | Kept | Kept (loss) | -- |
| GGUF | Yes | Yes | Yes | Yes [5] | Yes | Part [6] | No | Kept [7] | -- | Kept |
| HDF5, Keras v1-v2 | Yes | -- | -- | -- | Yes [8] | Part [9] | Part [10] | -- | Kept [11] | Kept |
| Keras v3 | Yes | -- | -- | -- | Yes [8] | Part [9] | Part [10] | -- | No [12] | Kept |
| NumPy | -- | -- | -- | -- | Fixed | -- | No [13] | -- | -- | Kept [13] |
| ONNX | Part [14] | Yes | Yes [15] | Yes [16] | Part [17] | -- | Yes [17] | -- | -- | Kept [18] |
| PyTorch classic | -- | -- | -- | -- | Part [19] | No | No | -- | No | Kept [20] |
| PT2 / ExecuTorch | Yes | Yes | Yes | Yes | -- | -- | Part [21] | -- | -- | Kept [20] |
| Safetensors | Part [22] | Part [22] | Part [22] | Part [22] | Part [22] | -- | No [23] | -- | -- | Kept |
| Hugging Face Hub | Yes | Yes | -- | Yes [24] | Yes | Part [25] | -- | No | Kept [26] | Kept |

1. Generated by Pitloom from the labels (`Method: generated_from_labels`),
   not written by the model's producer.
2. One output. CRFsuite: `label_sequence`, shape `["sequence_length"]`, a
   symbolic length as an ONNX `dim_param` (a tagger emits one label per
   input item); the label count is `num_labels`. fastText, supervised
   models only: `label_probabilities`, shape the label count. The file
   states neither output: Pitloom names it from the format
   (`Method: derived_from_format`). Feature
   weights and CRFsuite attribute strings (training-text features) are
   never read. A model over a label cap keeps its counts but no label (see
   [scan limits](ai-model-scan-limits.md#size-and-count-caps)).
3. `args.model` (`supervised`, `cbow`, `skipgram`). The domain is fixed:
   `natural language processing`, plus `text classification` for a
   `supervised` model (`Method: derived_from_format`). Labels and outputs are read from a `supervised`
   model only: for `cbow` and `skipgram`, fastText's label list is the
   word vocabulary (training text).
4. 9 of the training `args`: `bucket`, `dim`, `epoch`, `maxn`, `minCount`,
   `minn`, `neg`, `wordNgrams`, `ws`. `lr` and `minCountLabel` are not in the
   file (a loaded model reports their defaults), so they are not read. `maxn` is
   skipped for a supervised model of file version 11, which the loader resets.
5. `general.license` (an SPDX expression by the GGUF spec), trimmed and
   classified like any model licence; only a non-blank string counts
   (`general.version` may also be a number, read as its text). With no
   `general.license`, or one that is a placeholder (`other`, `custom`,
   `proprietary`, `unknown`, `unlicensed`, `NOASSERTION`; llama.cpp writes a card's
   `license: other` that way), `general.license.name` (the licence's name)
   stands in, trimmed. `general.license.link` is not read.
6. Keys ending `.context_length`, `.embedding_length`,
   `.feed_forward_length`, `.block_count`, `.attention.head_count`,
   `.attention.head_count_kv`, `.attention.layer_norm_rms_epsilon`,
   `.rope.freq_base`, `.rope.dimension_count`; plus `quantization`, the name
   of `general.file_type` when it is an integer other than `GUESSED` (1024,
   not stated). Every other key is kept.
7. An array (a tokenizer vocabulary, scores, per-layer values) is recorded
   by length only: `{"length": "N", "type": "<element type>"}` in the
   annotation (`type` left out for an element code the format does not
   define); its elements are never read.
8. The Keras class name (`Sequential`, `Functional`, ...).
9. The scalar entries of the model `config`.
10. The input shape only (Keras v3 `build_config`; v1-v2 the first layer's
    `batch_input_shape`). No outputs.
11. Optimiser class name, loss and metrics names from `training_config`.
12. `compile_config` is not read.
13. An array is data, not a model input, so there are no inputs. An `.npy`
    file's shape and dtype are kept as `properties` `array_shape` (`2x2`,
    `scalar` for none) and `array_dtype`; an `.npz` archive's array count as
    `array_count`.
14. `graph.name`, unless blank or an exporter default (`torch_jit`,
    `main_graph`, `tf2onnx`, ...).
15. `model_version`; a bit-packed SemVer value (any of its upper 32 bits
    set) as `MAJOR.MINOR.PATCH`
    ([ONNX versioning](https://onnx.ai/onnx/repo-docs/Versioning.html)).
16. The standard `model_license` metadata property
    ([ONNX IR optional metadata](https://onnx.ai/onnx/repo-docs/IR.html#optional-metadata)).
17. Type of model `neural network`, unset when a node uses an ONNX-ML
    operator (`ai.onnx.ml`: trees, linear models, SVMs); the opset import
    alone does not count (tf2onnx adds it to plain networks). Each input
    and output has its name, shape (`dim_param` names kept as text) and
    dtype by its NumPy name (`float32`, `int64`), or ONNX's own, lowercased,
    for a type NumPy lacks (`bfloat16`, `string`); no shape for an unknown
    rank or a non-tensor value (a sequence). An initializer (weight) that
    an IR version 3 graph also lists in `graph.input` is not an input; from
    IR version 4 on, a name in both is an input with a default, and kept.
18. `domain`, `opset.<domain>` and every `metadata_props` entry as
    `metadata_props.<key>`; a repeated key keeps its last value, with one
    `WARNING:` per file.
19. The class at the top of `data.pkl` (often `OrderedDict` for a state
    dict), found by `fickling` without running the pickle.
20. The archive member list and count; for PT2 also `extra/author` (also
    the producer; see [Producer and parameter count](#producer-and-parameter-count))
    and `extra/tags`. PT2 name, description, version and licence come from
    `extra/` (or `METADATA.json` and a root `version` file).
21. Tensor names from `models/model.json`, no shapes: only the `user_input`
    entries of its `signature.input_specs` and the `user_output` entries of
    `output_specs`. Parameters, buffers and constants are placeholders of the
    graph, not inputs; a file without a signature gives none.
22. Only from conventional `__metadata__` keys: name `modelspec.title`,
    `name` or `ss_base_model_version`; description `modelspec.description`
    or `description`; version `modelspec.version` or `version`;
    architecture `modelspec.architecture` or `architecture`; quantisation
    `modelspec.precision` or `precision`; producer `modelspec.author`;
    licence `modelspec.license` (a name or an expression, trimmed). No other
    licence key is read: none appeared in the 9 headers measured (SDXL base,
    SDXL refiner, SDXL Turbo and Stable Cascade write `modelspec.license`;
    GPT-2, Qwen2.5, Whisper, sd-vae-ft-mse and lcm-lora-sdxl do not).
23. Tensor names are weights, not a model's inputs: not recorded.
24. Model card `license`, or a licence file detected when the card has none
    or a vague one. Also from the Hub: DOI, arXiv IDs, page URL, base model,
    datasets, domains (pipeline tag).
25. Selected values of `config.json` and `generation_config.json`.
26. The model card's `model-index` evaluation results, as read.

## Producer and parameter count

Two values the G7 SBOM-for-AI minimum elements ask for are read from
structured fields only. A value that sits in free text (a model card's
prose) is left to [the `sbom-enrich` Skill](agent-skills.md).

| Format | Producer (`originators`) | Supplier (`supplier`) | Parameter count (`parameter_count`) |
| :----- | :----------------------- | :-------------------- | :---------------------------------- |
| GGUF | `general.author`, then `general.organization`: one name each | -- | Sum over the shapes in `tensor_infos`; none when `split.count` is above 1 |
| ONNX | `model_author` metadata property: a comma-separated list | -- | Sum over `graph.initializer` and `graph.sparse_initializer`, subgraphs included |
| PT2 / ExecuTorch | `extra/author`: one name | -- | -- |
| Safetensors | `modelspec.author` in `__metadata__` (ModelSpec): one name | -- | Sum over every tensor shape in the header (header only) |
| Hugging Face Hub | The repository owner (`author`): one name | The same name | `safetensors.total`, else `gguf.total`, as the Hub states it |

In the provenance the values are keyed by their field names, `originators`,
`supplier` and `parameter_count`.

Every other format gives neither: PyTorch classic (no shapes without
unpickling), Keras and HDF5 (the weights are not read), NumPy (a bare array
is not a model), fastText (its matrix size follows the dictionary stream) and
CRFsuite.

**Producer and supplier.** Each name becomes a generic SPDX `Agent` (name
only, no email) in the `ai_AIPackage`'s `originatedBy`, one Agent per
distinct producer name, shared when two models name the same one, and with a
dataset creator of that name (an SBOM creator of type `agent`, a main-package
author and a dependency's author are other elements and are not merged with
it). No model
file format sets `suppliedBy`: an author written in a file originated the
model, and the file does not say who ships it. A model read from the Hugging
Face Hub is the exception: the Hub repository is where the model is shipped
from, so its owner is also the `suppliedBy`, and the same one `Agent` is
referenced by both properties. `suppliedBy` holds one agent, so one owner. A
model never inherits the main package's `suppliedBy` (the SBOM's first
creator, which says nothing about the model). Whether a name is a person or
an organisation is not decided here; a [fragment](fragments.md) can add a
`Person` or `Organization` to `originatedBy` when the model card says which
(lists merge by union, so the generic `Agent` stays beside it). Things to
know:

- ONNX defines `model_author` as a comma-separated list, so the text is
  split on commas, and `Method: comma_list` is recorded when it has one. A
  name that itself holds a comma (`Doe, Jane`, `Foo, Inc.`) is split wrongly.
- The Hub's `author` is the account that owns the repository, recorded with
  `Method: repository_owner` for both `originators` and `supplier`. A
  re-upload, quantisation or fine-tune names the uploader, not the original
  maker; the base model a card names is recorded separately as
  `descendantOf`, which records lineage only.
- GGUF, PT2 and Safetensors names are not split: `general.author`,
  `extra/author` and `modelspec.author` hold one name. The raw keys also
  stay in `properties`.
- The llama.cpp converter often fills GGUF `general.organization` by
  guessing from the base model's `_name_or_path`, so a fine-tune's file can
  name the base model's organisation. Pitloom reads it as stated and cannot
  tell a stated organisation from a guessed one. The Hub route names the
  repository owner instead, so the same model can show two producers by
  route.
- A name over the length cap is cut; several over-long names in one model
  give one warning, not one per name (see
  [scan limits](ai-model-scan-limits.md#size-and-count-caps)).

**Parameter count.** SPDX 3.0.1 has no property for a model's size, so the
count is an `ai_hyperparameter` entry, key `parameters`, value a decimal
integer as text (`"7241732096"`). The G7 SBOM for AI mapping to SPDX
(bact.github.io/bom) names this key for the parameter count. It is not a
hyperparameter, and the package `comment` says so, in this line, whenever
the entry is there:

```text
Parameter count: ai_hyperparameter "parameters" holds the number of elements in the model's stored tensors, as its parameter count, because SPDX 3.0.1 has no model-size property (it is not a hyperparameter).
```

A [fragment](fragments.md) merge keeps the line in step with the entry for
each package it merges into: afterwards the package has the line first in its
`comment` if it has a `parameters` entry that is a positive decimal integer
(ASCII digits, up to 10^15) and none otherwise, whatever a fragment's `comment`
says (a base `parameters` entry wins over a fragment's). A value such as `7B`
gets no line. A package that no fragment merges into keeps its `comment` as
written. A merge cannot tell a model's own `parameters` entry from a count, so
it labels that too.

- A count read from the file is the sum of the **element** counts of its
  tensors, not bytes: a `[32, 2]` tensor adds 64 whatever its type. It is
  recorded with `Method: tensor_element_sum`, as is the Hub's: its
  `safetensors.total` (or `gguf.total` when there is no `safetensors` field;
  `safetensors` wins when both exist) is the same sum, computed by the Hub.
  The provenance reads `Source: Hugging Face Hub | Field: model_info
  safetensors.total | Method: tensor_element_sum`.
- ONNX counts every tensor in `graph.initializer` and
  `graph.sparse_initializer` and in subgraphs, a tensor stored in an
  external data file by its declared dimensions (the file is not read).
  `Constant` nodes and `model.functions` are not counted.
- A Safetensors file that is one shard of a model gives that file's count,
  and the format has no sign that it is a shard. A GGUF file with
  `split.count` above 1 gives none, since its sum would understate the model.
- A sum of 0, or a file with no tensor, gives no count (never `"0"`), with
  no message. A malformed dimension (negative, not an integer) or a count
  over 10**15 gives none and one `WARNING:` ending `parameter count not
  recorded`; see [scan limits](ai-model-scan-limits.md#size-and-count-caps).
- A hyperparameter the model itself declares under the key `parameters` is
  replaced by the count, with a `WARNING:`.

### What the count counts

It is the number of elements of **all** stored tensors, not the "trainable
parameters" of a size such as `bom:ai-model-size`. Do not filter by type:
int8 weights are parameters.

- It includes buffers stored as tensors (attention masks, shape constants)
  and tied weights stored twice. The ONNX test model `gpt2-tiny-decoder`
  counts 404256, which includes a 262144-element uint8 causal mask
  (`transformer.h.0.attn.bias`, `[1, 1, 512, 512]`) and a 32000-element
  transposed copy of `wte.weight`; about 110112 are weights of their own. A
  tiny Marian Safetensors model's 174535 includes the 58101-element
  `final_logits_bias` buffer, and `squeezenet1.1-7`'s 1235498 is 1235496
  weights plus a 2-element int64 reshape constant. The Hub API gave
  137022720 for `openai-community/gpt2` (2026-10-15), against about 124.4
  million weights: attention-mask buffers make up the rest.
- Packed or quantised weights count differently by format. GGUF shapes are
  logical (a Q4_0 tensor of shape `[64]` counts 64). GPTQ, AWQ and
  bitsandbytes Safetensors files store packed integer tensors: a GPTQ-style
  64 x 64 layer with `qweight` (I32 `[8, 64]`), `scales`, `qzeros` and
  `g_idx` counts 648 against 4096 real weights. Block-quantised ONNX
  (`MatMulNBits`) under-counts likewise.
- The Hub's `safetensors.total` and `gguf.total` have the same property. For
  a repository of several components, such as the diffusion pipeline
  `stabilityai/stable-diffusion-xl-base-1.0`, whose `safetensors.total` is
  the UNet only, the Hub's total may cover only part of the repository.

## Where each field goes

One row per field of `AiModelMetadata` (`pitloom.core.ai_metadata`), one
column per output format. Formats are named as in the tables above; "HF" is
the Hugging Face Hub, "card" a README or model card read with `--enrich`.

| Field | Filled by | SPDX 3.0.1 JSON-LD |
| :---- | :-------- | :----------------- |
| `name` | GGUF, ONNX, Keras, HDF5, PT2, Safetensors, HF | `ai_AIPackage.name`; without one, the file name's stem (`Method: file_name_stem`), else the format |
| `description` | GGUF, ONNX, PT2, Safetensors, CRFsuite, HF | `ai_AIPackage.description` |
| `version` | GGUF, ONNX, PT2, Safetensors, HF (the revision's 40-digit commit hash) | `ai_AIPackage.software_packageVersion` |
| `release_time` | HF (the revision's last-modified time) | `ai_AIPackage.releaseTime`, in UTC; a time that is not ISO 8601 is left out with a `WARNING:` |
| `license` | ONNX, PT2, HF, card | licence element plus `hasDeclaredLicense` (the model's own statement) or `hasConcludedLicense` (a third-party source); see [How a licence value is recorded](metadata-provenance-licences.md#how-a-licence-value-is-recorded) |
| `originators` | GGUF, ONNX, PT2, Safetensors, HF | `ai_AIPackage.originatedBy`: one generic `Agent` per name; see [Producer and parameter count](#producer-and-parameter-count) |
| `supplier` | HF | `ai_AIPackage.suppliedBy`: the repository owner's generic `Agent`, the one in `originatedBy` when the name is the same; no file format fills it |
| `type_of_model` | CRFsuite, fastText, HDF5, Keras, NumPy, ONNX, PyTorch, HF | `ai_typeOfModel`, first entry |
| `architecture` | GGUF, Safetensors, HF | `ai_typeOfModel`, after `type_of_model`; one `INFO:` line per model says it has no property of its own |
| `quantization` | GGUF, Safetensors | `ai_hyperparameter`, key `quantization`, first |
| `parameter_count` | GGUF, ONNX, Safetensors, HF | `ai_hyperparameter`, key `parameters`, decimal integer as text, among the entries sorted by key; with it a line in `ai_AIPackage.comment` saying it is not a hyperparameter (SPDX 3.0.1 has no model-size property); what it counts: [What the count counts](#what-the-count-counts) |
| `hyperparameters` | GGUF, fastText, HDF5, Keras, HF | `ai_hyperparameter`, one `DictionaryEntry` per key, sorted by key, value as text |
| `domain`, `usage.domains` | fastText, HF | `ai_domain` |
| `inputs`, `outputs` | see the table above | `ai_informationAboutApplication`, JSON keys `inputs`, `outputs` |
| `usage.intended_use`, `usage.unintended_use` | none today | `ai_informationAboutApplication`, JSON keys `intended_use`, `unintended_use` |
| `usage.limitations` | none today | `ai_limitation`, joined with `; ` |
| `usage.safety_risk_assessment` | none today | `ai_safetyRiskAssessment` (`high`, `medium`, `low`, `serious`) |
| `usage.known_biases` | none today | `ai_AIPackage.comment`, `Known biases: ...`, after the parameter-count line when both are there |
| `doi` | HF | `externalIdentifier`, type `other`, comment `DOI` |
| `arxiv_ids` | HF | `externalRef`, type `documentation` |
| `url` | HF | `externalRef`, type `altWebPage` |
| `base_model`, `base_model_relation` | HF | `Relationship` `descendantOf` to an `ai_AIPackage` for the base model (made if absent); the relation in its `comment` |
| `datasets` | HF, card | `dataset_DatasetPackage` plus `Relationship` `trainedOn` or `testedOn`; references to one dataset (a Hub id in any letter case, or one name with different spacing) give one package with one relationship per role, a later reference only filling what the first leaves unset; a licence the dataset's metadata states becomes a licence element and `hasDeclaredLicense` (or `hasConcludedLicense` for a third-party source), as for the model. A Hub card's dataset gets the licence, description, revision and owner of its own Hub dataset repository (see [Hugging Face Hub models](#hugging-face-hub-models)) |
| `properties`, `raw_metadata`, `raw_metadata_types` | every format | `Annotation` of kind `artifact-metadata` (schema `https://pitloom.dev/provenance/artifact-metadata/2`): `metadata`, `valueTypes`, `format`; only when preserved, see below |
| `raw_metadata_dropped` | any format, over the entry cap | that annotation's `truncatedKeyCount` |
| `extra_data`, `extra_lists` | HF | that annotation, `format` `huggingface` |
| `provenance` | every format | `ai_AIPackage.comment` (`Metadata provenance: ...`) and/or a provenance `Annotation`, by `[tool.pitloom.provenance] format` |
| `format_info.model_format` | every format | the artifact-metadata annotation's `format` |
| `format_info.format_version`, `framework`, `framework_version` | most formats | not written: cited in the provenance only |
| `format_info.file_path_relative` | project and wheel scans | `Relationship` `contains` from the `ai_AIPackage` to the model's `software_File` (which has the SHA-256 and SHA-512) |
| `usage_files` | `--scan-model-usage` | `LifecycleScopedRelationship` `hasDataFile`, scope `runtime`, from each `.py` `software_File` to the model's |

The artifact-metadata annotation is written when
`preserve-source-metadata` says so: by default (`auto`) only for a model
whose file is not in the SBOM's file list, as with `loom model FILE`; see
[Preserved artefact metadata](metadata-provenance-artifact-metadata.md#preserved-artefact-metadata).
In it a collection is a JSON array (or object) and a scalar is text, for
every format.

Text a model's source wrote is untrusted: bidi and zero-width controls in
the properties shown to a reader are written as `\uXXXX`, with one
`WARNING:` per model, while the artifact-metadata annotation keeps the text
as read. Which properties, and how to read them back: [Reading values
back](metadata-reading-back.md). Long names and labels are capped: see
[scan limits](ai-model-scan-limits.md#size-and-count-caps).

No model format fills `ai_metric`, `ai_metricDecisionThreshold`,
`ai_energyConsumption`, `ai_autonomyType`, `ai_modelDataPreprocessing`,
`ai_modelExplainability`, `ai_sensitivePersonalInformation`,
`ai_standardCompliance` or `software_primaryPurpose` on an `ai_AIPackage`;
an [SBOM fragment](fragments.md) can add them. Nor
does any model file format fill `suppliedBy`, on purpose: a producer name is
an `originatedBy`; only the Hugging Face route sets it, to the repository
owner (see [Producer and parameter count](#producer-and-parameter-count)).

Two properties come from the file or the repository, not from a format
field:

- `verifiedUsing`: the model file's SHA-256 and SHA-512, from one read,
  whenever Pitloom read the file. A Hugging Face model has none.
- `software_packageUrl`: `pkg:huggingface/<owner>/<name>@<commit>` for a
  Hugging Face model (the commit only when the Hub gave a 40-digit hash; an
  ID with no owner, such as `gpt2`, gets none); otherwise
  `pkg:generic/<file name>?checksum=sha256:<digest>` for a hashed model file.
  A dataset with an `http://` or `https://` download URL gets
  `pkg:generic/<name>[@<version>]?download_url=<url>`.

## Hugging Face Hub models

Pass a Hugging Face Hub URL or a bare model ID instead of a local file --
no download required for the SBOM itself (needs
`pip install pitloom[huggingface_hub]`):

```bash
loom model https://huggingface.co/mistralai/Mistral-7B-v0.1
loom model Qwen/Qwen3-235B-A22B
```

The `www.huggingface.co` and `hf.co` forms, `http://` and any case of the host
are read as `https://huggingface.co/...`, with an `INFO:` line saying so.

This reads the model card, `config.json`, `tokenizer_config.json`,
`generation_config.json` and the Hub's model information, and produces an
`ai_AIPackage` as in the tables above.

For each dataset the model card lists (`datasets:`, else the Hub's
`dataset:*` tags) that is a Hub repository id, Pitloom also reads that
dataset's own card and repository information, the first 20 datasets only. A dataset listed twice (a Hub id is
case-insensitive, so `O/D` is `o/d`) is one dataset, and a card lists at most
1000, with one `WARNING:` when it lists more:

| Dataset field | From | Provenance `Field:` |
| :------------ | :--- | :------------------ |
| licence | the card's `license`; for `other`, its `license_name` and `license_link` (name first); `unknown`, `N/A`, `NOASSERTION` or an `other` with no real name or link give none; a list of several gives one `hasDeclaredLicense` each, in order, and a package comment that the card does not say whether they combine as AND or OR | `dataset card license` |
| description | the card's first prose paragraph; a table of contents, key lines (`**Paper:** [...]`), badges, HTML, tables and code blocks are passed over | `dataset card` |
| keywords (not written: SPDX 3.0.1 has no dataset keyword property) | the card's `tags` | `dataset card tags` |
| version | the repository's commit hash | `dataset_info sha` |
| creator (`publishedBy`) | the repository owner | `dataset_info author`, `Method: repository_owner` |

A field the dataset does not state is left out. A failed request (a network
error, a gated, private or deleted dataset) or a card that cannot be read is
one `WARNING:` naming the dataset (never a path in the local cache), which keeps its name and download URL. These requests run only when
the model itself is looked up, so `--offline` stops them too.

## Not yet supported

JAX (Orbax), TensorFlow SavedModel, TensorFlow Lite, and scikit-learn
(pickle/joblib) are on the roadmap but not implemented yet.

## Adding a format

The tables are kept one row per model format and per field, one column per
output format, so that either grows by one line or one column.

- **A new SBOM output format** (CycloneDX, another SPDX version): add a
  column to [Where each field goes](#where-each-field-goes). The SPDX 3
  mapping lives in `pitloom.assemble.spdx3._ai_package` and
  `pitloom.assemble.spdx3.ai`; a new format gets its own assembler that
  reads the same `AiModelMetadata`.
- **A new model format**: fill every field the format can express the way the
  existing formats do (licence, producer, parameter count, version), and read
  only what the file itself stores: a value a binding returns as a default, or
  resets by version, is not the file's (fastText's `lr` is one). Then add a
  row to the tables in
  [How a file is recognised](#how-a-file-is-recognised) and
  [What each format holds](#what-each-format-holds), and its name to the
  "Filled by" cells it fills. In code: an `AiModelFormat` member (suffixes,
  magic) in `pitloom.core.ai_metadata`; a reader in
  `pitloom.extract.ai_model` (a library-free header reader goes in its
  `formats` subpackage), registered in `REGISTRY` in
  `pitloom.extract.ai_model.reader` (and in `_EXTENSION_ADMITS` there when
  the format has no magic); its library in
  `pitloom.extract.ai_model.reader_requirements` and a `pyproject.toml`
  extra; a decision on the wheel gate
  (`pitloom.extract.scanner_wheel.WHEEL_GATED_FORMATS`); and fixtures
  under `tests/fixtures/aimodels/`. A reader that knows the producer or the
  tensor shapes fills `originators` with `originator_names()`
  (`pitloom.core.model_originators`, which bounds the read; the reader
  records the `originators` provenance) and `parameter_count` with
  `derived_parameter_count()` (`pitloom.extract.ai_model.parameter_count`,
  which bounds the sum and records its provenance); it does not build an
  `Agent` or an entry itself.
