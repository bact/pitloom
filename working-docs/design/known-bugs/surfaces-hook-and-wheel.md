# Known bugs: CLI, Action, hook and wheel

See also: [known-bugs.md](../known-bugs.md) (index, severity scale,
rules for adding an entry), [roadmap.md](../roadmap.md),
[github-action.md](../../implementation/github-action.md).

The surfaces (CLI, GitHub Action, library, Hatchling hook) and wheel handling:
options, output paths, signals and platform differences. Entries are ranked by
priority tier, then by size tag; see the severity scale in the index. Open
entries come first; fixed entries stay in the last section for history.

## Open

### P3: after 0.20.0

- [ ] **Action `output: "-"` sets `sbom-path=-` (S).** The upload step then
  fails on a path named `-`. Refuse `-` in `action.yml`, or write the SBOM
  to a file (#288 review).
- [ ] **Library docs never say `output_path="-"` means stdout (S).**
  `write_sbom_output` gives every generator and `embed_wheel_sbom()` that
  meaning; neither the docstrings nor `docs/python-api.md` state it, and no
  library-level test pins it (#288 review).
- [ ] **GitHub Action drops invalid boolean inputs silently.** Any
  non-empty value other than exactly `true`/`false` (`maybe`, `True`) on
  the tri-state `enrich`, `extract-file-header`, `update-id-registry`,
  `content-type`, `offline`, `use-lockfile`, and on the two-state
  `pretty`, `allow-build`, `no-build-isolation` (case-sensitive
  `= "true"`, so `allow-build: True` skips the build) passes no flag and
  prints no warning; `use-lockfile` in model/embed-wheel mode is dropped
  silently too.
- [ ] Case-insensitive member-name collisions in wheels; `--allow-build`
  extraction keeps the last duplicate with a warning.
- [ ] A scan in a worker thread registers its temp-dir cleanup with its
  own guard, so the dir can outlive SIGTERM to the main thread.
- [ ] `embed-wheel` temp file on SIGTERM (P4): `BaseException` cleanup is
  in place; signals are still uncovered.
- [ ] Windows `--build-timeout`: when a process in the build tree exits on
  its own during `taskkill /F /T`, taskkill reports failure, so the
  `WARNING:` says "could not confirm the build process tree terminated"
  although it did. A Job Object would confirm it (0.21.0).

### Found in review rounds, not yet prioritised

- [ ] **`embed-wheel --sbom FILE` stores another format under a `.spdx3.json`
  name (S).** A valid CycloneDX `bom.cdx.json` is embedded as
  `<basename>.spdx3.json` (with the cross-check `WARNING:`):
  `_derive_wheel_sbom_filename` and `sbom_file_name` always add the SPDX 3
  extension. Decide: refuse a format Pitloom cannot name, or store it under its
  recommended extension (`.cdx.json`, PEP 770 allows any name).
  *Found 2026-10-28, 0.21.0 release review.*
- [ ] **The GitHub Action is covered for registry keys only through the CLI
  (S).** The Action's own step is not tested for them.
  *Found 2026-10-30, from #407 (registry package key).*

### Leads to verify

Seen in past sessions, not reproduced on current `main`:

- On Windows, `os.replace()` fails while another process holds the
  target open; the registry save should turn that into its existing
  "failed to save" `WARNING:`.
- Windows: `METADATA.` and `METADATA::$DATA` map onto `METADATA`; case
  variants of `.dist-info` names overwrite each other on macOS and
  Windows.

## Fixed

Kept for history, with the PR. A fixed entry moves to
[roadmap-completed.md](../../implementation/roadmap-completed.md) once its
release ships.

### Fixed, P0: in 0.21.0

- [x] **One default SBOM file name on every surface (S-M), built in #334** with
  one helper; the character rule differs from the PEP 427 escaping decided here.
  Original entry: `loom
  project` writes `Foo.Bar-Baz-1.0+local.spdx3.json` unescaped; the
  Hatchling hook uses the raw name; embed's escaper skips `*?"<>|`.
  Decided: PEP 427 escaping everywhere, its own PR.

### Fixed, P3: after 0.20.0

- [x] **`--help` choice order changes per run (S).** Fixed (06d7cc45): `cli/parser.py`
  passes `choices=sorted(VALID_CONTENT_TYPE_METHODS)` and
  `sorted(VALID_CREATOR_TYPES)`. (Was: a frozenset in hash order.)
- [x] **`loom.run` never calls `configure_logging()` (S).** Fixed by
  registry v3 (PR #305): `loom.Run` configures logging first, so its messages
  carry their `WARNING:`/`INFO:` tag. The `loom: ...` sub-prefix (against
  `ID registry: ...` elsewhere) is kept on purpose, and the example's
  committed registry is regenerated by its pipeline script.
- [x] **`-v` logs `OUTPUT_PATH=-` for both "no copy" and "copy to stdout"
  (S).** Fixed by #429: `wheel --embed -v` leaves the key out when no copy is
  written; `-o -` still logs `OUTPUT_PATH=-`. (Was: `wheel --embed -v` (no
  `-o`) and `wheel --embed -v -o -` printed the same line (#288 review).)

### Fixed, Found in review rounds, not yet prioritised

- [x] **`embed-wheel --sbom FILE` embeds a file it cannot parse or read as SPDX 3
  (S).** Fixed in 0.22.0 (#374): `pitloom._sbom_format.refuse_unusable_given_sbom`
  refuses invalid JSON, a non-object and a `.spdx3.json` that is not SPDX 3
  before the wheel is written. Malformed JSON named `x.spdx3.json` was
  embedded with a skip `WARNING:` (exit 0), where `fragment validate` says
  `ERROR: Invalid JSON`; a CycloneDX file named `.spdx3.json` is now refused
  too. Parse failure of a
  file the user named should be an error before the wheel is written.
  *Found 2026-10-28, 0.21.0 release review.*
